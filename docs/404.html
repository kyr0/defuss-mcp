TypeScript functions, served as MCP tools.

Register an object of functions. defuss-mcp publishes them to every Model Context Protocol client over stdio, Express, bunway or any Fetch handler. Agents read named schemas and repair rejected calls, and TypeScript callers get the original types back.

Run it in this page Benchmark 
bun add defuss-mcp
npm install defuss-mcp
pnpm add defuss-mcp
yarn add defuss-mcp
import { createMcpApi } from 'defuss-mcp';
import { createMcpHttp } from 'defuss-mcp/http';
const identity = { name: 'greeter', version: '1.0.0' };
const functions = { greet: (name: string) => 'Hello, ' + name };
export const api = createMcpApi(identity, functions, {
  metadata: { greet: { annotations: { readOnlyHint: true } } },
});
const endpoint = createMcpHttp(api);
Bun.serve({ port: 3000, fetch: (req) => endpoint.fetch(req) });

await tools.greet('Ada') "Hello, Ada" : string

#What you get from one registry

Functions become tools

Pass { add, greet } to createMcpApi. Object keys are tool names, so bundling and minification never rename a tool.

Agents repair their own calls

A generated contract turns the signature and JSDoc into named JSON Schema. A rejected argument returns its JSON Pointer and an instruction, not a stack trace.

Bytes and rich values arrive intact

Typed arrays travel as base64 trees, and Maps, BigInts, Dates and cycles use DSON. A plain JSON client still sees ordinary schemas.

One catalog, any host

stdio, Express, bunway and Fetch share one frozen catalog in JSON, SSE or automatic Streamable HTTP reply mode. Your application keeps its listener.

Your guards keep running

Authorization sees every HTTP exchange, and the defuss-rpc bridge re-enters the RPC dispatcher, so method guards also apply to MCP callers.

Hints for the host

Titles and annotations such as readOnlyHint and destructiveHint reach tools/list, where hosts decide whether to ask before a call.

How it works

#Write a function. Every client can call it.

The registry freezes its catalog when the first transport starts. Each HTTP request gets its own SDK server with its own headers and cancellation signal, while every request shares the compiled schemas.

  1. 1

    Register

    An object of functions, a tuple, or explicit .json, .dson and .binary tools with their own schemas.

  2. 2

    Describe

    bunx defuss-mcp reads exports and JSDoc and writes named schemas that agents can discover.

  3. 3

    Mount

    Hand the registry to createMcpHttp or serveMcpStdio. Your host keeps its routes, listener and authentication.

  4. 4

    Call

    getMcpClient<typeof api> returns typed functions. Every other MCP client uses the advertised schemas.

Five runtime dependencies: the official MCP server SDK and its Node adapter, Ajv with its formats, and defuss-dson.
      
      
      
    
      
    
      
      
      
        
        
        
        
        
      
      
      
      
        
      A Fetch handler serves Streamable HTTP. The same endpoint works in any router that passes a Request.
      
        
      // server.ts, run with: bun server.ts
      

      import { createMcpApi } from 'defuss-mcp';
      

      import { createMcpHttp } from 'defuss-mcp/http';
      

      

      export const api = createMcpApi(
      

        { name: 'greeter', version: '1.0.0' },
      

        { greet(name: string) { return 'Hello, ' + name; } },
      

        { metadata: { greet: { title: 'Greet', annotations: { readOnlyHint: true } } } },
      

      );
      

      const endpoint = createMcpHttp(api);
      

      Bun.serve({ hostname: '127.0.0.1', port: 3000, fetch: (request) => endpoint.fetch(request) });
      

      

      // client.ts: the official SDK client with typed functions
      

      import { Client, StreamableHTTPClientTransport } from '@modelcontextprotocol/client';
      

      import { getMcpClient } from 'defuss-mcp/client';
      

      import type { api } from './server.ts';
      

      

      const sdk = new Client({ name: 'caller', version: '1.0.0' });
      

      await sdk.connect(new StreamableHTTPClientTransport(new URL('http://127.0.0.1:3000/mcp')));
      

      const { tools } = await getMcpClient<typeof api>(sdk);
      

      console.log(await tools.greet('Ada')); // "Hello, Ada", typed as string
      
      
      
      
      
        
      Mount the endpoint on your route. authorize sees every exchange, including discovery; validation returns corrections instead of running the handler.
      
        
      import express from 'express';
      

      import { createMcpApi } from 'defuss-mcp';
      

      import { createMcpHttp } from 'defuss-mcp/http';
      

      import { ajvValidator } from 'defuss-mcp/validation';
      

      

      const tools = createMcpApi({ name: 'arithmetic', version: '1.0.0' }, { compile: ajvValidator() });
      

      tools.json<{ a: number; b: number }>('add', {
      

        type: 'object',
      

        properties: { a: { type: 'number' }, b: { type: 'number' } },
      

        required: ['a', 'b'],
      

        additionalProperties: false,
      

      }, ({ a, b }) => a + b, { description: 'Add two numbers.', annotations: { readOnlyHint: true } });
      

      

      const token = process.env.MCP_API_TOKEN;
      

      if (!token) throw new Error('Set MCP_API_TOKEN before starting the server.');
      

      const endpoint = createMcpHttp(tools, {
      

        authorize: (request) => request.headers.get('authorization') === 'Bearer ' + token,
      

      });
      

      const app = express();
      

      app.all('/mcp', endpoint.middleware);
      

      app.listen(3000, '127.0.0.1');
      
      
      
      
      
        
      A desktop host launches the server as a child process and speaks MCP over its pipes. Keep stdout for the protocol and log to stderr.
      
        
      import { createMcpApi } from 'defuss-mcp';
      

      import { serveMcpStdio } from 'defuss-mcp/stdio';
      

      

      const notes = ['Ship the release', 'Review the client matrix'];
      

      const api = createMcpApi({ name: 'notes', version: '1.0.0' }, {
      

        search(query: string, limit = 10) { return notes.filter((note) => note.includes(query)).slice(0, limit); },
      

      });
      

      api.observeCalls((event) => {
      

        process.stderr.write(JSON.stringify({ time: new Date().toISOString(), level: 'info', ...event }) + '\n');
      

      });
      

      const handle = await serveMcpStdio(api);
      

      process.once('SIGTERM', () => void handle.close());
      
      
      
      
      
        
      The contract generator reads exports, imported interfaces and JSDoc, and writes a binding module next to the source. --check fails CI on stale output.
      
        
      bunx defuss-mcp --entry src/math.ts --out src/math.mcp.ts
      
        
      // math.ts
      

      /** Add equal-length byte arrays elementwise, modulo 256. */
      

      export function add(a: Uint8Array, b: Uint8Array): Uint8Array {
      

        if (a.length !== b.length) throw new RangeError('Expected equal lengths.');
      

        return a.map((value, i) => value + b[i]!);
      

      }
      

      

      // server.ts: a stock client now sees { a: base64, b: base64 } and gets corrections at /a or /b
      

      import { createMcpApi } from 'defuss-mcp';
      

      import { add } from './math.mcp.js';
      

      export const api = createMcpApi({ name: 'math', version: '1' }, { add });

        API
        
      #One small API covers every MCP protocol
      
        
      The same registry answers the two newest MCP revisions: 2026-07-28, which clients find through server/discover, and 2025-11-25 with its initialize handshake. It serves them over stdio and Streamable HTTP, with JSON, SSE or automatic replies. With automatic negotiation, the official TypeScript client selects 2026-07-28.
      
      
      
    
      
    
      
      
      
        
      ImportCallWhat it does
      
        
          
      defuss-mcpcreateMcpApi(identity, functions, options)Registers an object or tuple of functions; options set the schema compiler, the error sink and per-tool metadata.
      
          
      defuss-mcp.json, .dson, .binary, .groupAdds tools with a hand-written schema, a DSON graph, base64 bytes, or a staged batch that publishes atomically.
      
          
      defuss-mcp.observeCalls, .processCallsReceives start and finish events with durations, or transforms decoded inputs and results.
      
          
      defuss-mcp/httpcreateMcpHttp(registry, options)Returns fetch, middleware and close with host, origin, size and authorization checks.
      
          
      defuss-mcp/stdioserveMcpStdio(registry, options?)Serves the catalog on the process pipes of a child launched by the client. Reads stdin in linear time; maxMessageBytes bounds one message.
      
          
      defuss-mcp/clientgetMcpClient<typeof api>(sdk)Discovers the catalog once and returns typed remote functions over your connected SDK client.
      
          
      defuss-mcp/validationajvValidator()Compiles JSON Schema 2020-12 and draft-07 with formats; failures become pointer-based corrections.
      
          
      defuss-mcp/rpcexposeRpc(registry, rpcRoute, options)Publishes defuss-rpc methods as Namespace.method tools and dispatches through the RPC route and its guards.
