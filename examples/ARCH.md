# Shared listener example

The example registers one arithmetic module and one class with defuss-rpc. It mounts MCP routes on the provider's own app. The same file runs as a child process when invoked with stdio, which keeps the test and benchmark functions identical. Start and stop belong to the host application. An unknown provider name stops the process with a message instead of falling back to another provider.

byte-add.ts implements modular addition over equal-length views. The benchmark and observed-stdio.ts import the same function. The stdio example writes structured events to stderr and reserves stdout for SDK frames. The HTTP example writes its listening line as one JSON event with an ISO-8601 time, a level and the URL, which the test drivers parse. In stdio mode it writes transport errors, such as an oversized message, as one JSON line to stderr. Its `bytes.pattern` tool returns generated bytes, so the tests can download more than an HTTP request may carry.

math.mcp.ts is generated from the types and JSDoc in byte-add.ts. The shared example imports its bound function and forwards its contract to the guarded math RPC namespace.

The examples are TypeScript that Bun and Node run without a build step. A precompiled JavaScript copy would need its own build and could drift from the typed source. tsconfig.json allows `.ts` import specifiers, which Node's type stripping requires, and limits the files to erasable syntax. The generator reads the same file, so the published sidecar imports `./byte-add.ts`. Node refuses to strip types below node_modules, so consumers copy an example before running it.

VERIFIED: `make e2e` runs these files unbuilt. Node 24.22.3 serves Express and stdio, and Bun 1.4.5 serves Express, bunway, Fetch and stdio. In a manual run, each HTTP configuration exited within one second of SIGTERM.
